# PERFUSION MOBILE — FIX VIDEO CALL BLACK SCREEN + UNIFY CALL UI

Fix ONLY the mobile video-call experience in:

artifacts/perfusion-mobile

There are TWO connected problems:

PROBLEM 1 — CRITICAL VIDEO BUG

When a video call is active:

- I cannot see my own camera/video.
- I cannot see the provider's camera/video.
- The provider also cannot see my camera/video.
- The call interface is essentially showing a black screen instead of live video.

This happens on BOTH sides of the call.

Do NOT solve this by merely changing the black background color.

The actual local and remote video streams must render correctly.

AUDIT THE ENTIRE EXISTING CALL PIPELINE FIRST:

1. Find the mobile video-call screen/component.
2. Find where the local camera stream is created.
3. Find where the remote participant stream is received.
4. Find how localVideo / remoteVideo / MediaStream / RTCView / VideoView or the project's equivalent is connected to the UI.
5. Inspect the call/session initialization.
6. Inspect how the remote participant is identified.
7. Inspect camera and microphone permission handling.
8. Check whether the camera is actually enabled when a video call starts.
9. Check whether the remote track is being subscribed to/rendered.
10. Check whether the video component is mounted but receiving a null/empty stream.
11. Check whether z-index/layering/absolute positioning is hiding the video behind another black View.
12. Check whether the video component is being unmounted/re-mounted during call state changes.
13. Check outgoing and incoming call flows separately.

IMPORTANT:
Do not rewrite the calling architecture if the existing WebRTC/calling implementation is basically correct.

Find the smallest root cause and fix it.

The final functional behavior must be:

OUTGOING:
User A starts video call
→ User A sees their own camera
→ User B answers
→ User A sees User B's live video
→ User B sees User A's live video

INCOMING:
User B receives video call
→ User B answers
→ User B sees User A's live video
→ User A sees User B's live video

Both sides must receive actual live video.

CAMERA/PERMISSIONS:
Verify that camera and microphone permissions are correctly requested and available before starting the video session.

Do not silently fall back to a fake avatar or placeholder when the video stream should be available.

If a stream genuinely cannot connect, show a proper connection state such as:
Connecting...
Reconnecting...
Camera unavailable

Do NOT show an unexplained full black screen.
