Fix the global keyboard/input visibility issue across the Perfusion MOBILE APP.

IMPORTANT:
This is a MOBILE UI/UX and keyboard-handling fix.

Do NOT modify unrelated functionality, API behavior, database logic, authentication logic, navigation logic, or business rules.

==================================================
PROBLEM
==================================================

Currently, whenever the user taps an input field and the mobile keyboard opens, the keyboard covers the area where the user is typing.

This is happening across multiple screens/pages.

The problem is especially visible on the Login screen:

- Email/password inputs can become hidden behind the keyboard.
- The user cannot properly see the text/cursor while typing.
- The screen does not move/scroll enough to keep the focused input visible.

This must be fixed globally wherever text input fields are used.

==================================================
EXPECTED BEHAVIOR
==================================================

Whenever the keyboard opens:

1. The currently focused input must remain visible.
2. The area containing the focused input should automatically move/scroll above the keyboard.
3. The user must be able to see the text they are typing.
4. The cursor and input field must remain visible.
5. The user should still be able to scroll through the page normally.
6. When the keyboard closes, the screen should return to its normal position.
7. The solution must work across different Android screen sizes and keyboard sizes.

The keyboard must NOT simply cover the active input.

==================================================
LOGIN SCREEN — PRIORITY
==================================================

Fix the Login screen first.

Current layout includes approximately:

- Logo
- Sign In heading
- Sign in with Google
- Email input
- Password input
- Sign In button
- Create a new account

When the user taps:

EMAIL:
The email input must remain visible above the keyboard.

PASSWORD:
The password input must remain visible above the keyboard.

The password field must NOT be hidden behind the keyboard.

The user must be able to see the password input and cursor while typing.

The Sign In button should also remain accessible by scrolling if necessary.

Do not redesign the Login screen.

Only fix keyboard behavior/layout.

==================================================
GLOBAL FIX
==================================================

Do NOT solve this by adding random padding/margins to individual screens.

First inspect the mobile application's existing layout architecture.

Find:

- Root navigation layout
- Root Stack/Tabs
- Shared screen layout components
- Existing ScrollView usage
- Existing TextInput components
- Keyboard handling
- SafeAreaView usage
- Expo/React Native configuration
- Any existing KeyboardAvoidingView implementation
- Any existing keyboard-aware scrolling library
- Modal/bottom-sheet input screens

Determine whether there is already a common layout component that can be fixed once and benefit all screens.

Prefer a centralized solution.

==================================================
REACT NATIVE KEYBOARD HANDLING
==================================================

Use the appropriate React Native keyboard-handling approach for the project's existing Expo SDK/version.

Consider the correct combination of:

- KeyboardAvoidingView
- ScrollView
- FlatList
- contentContainerStyle
- keyboardVerticalOffset
- automaticallyAdjustKeyboardInsets where appropriate
- Safe Area handling

Do NOT blindly wrap every screen in multiple KeyboardAvoidingViews.

Avoid nested keyboard-handling components that can cause:

- Double movement

- Jumping layouts
- Incorrect scrolling
- Broken bottom navigation

==================================================
FOCUSED INPUT VISIBILITY
==================================================

The important requirement is not merely:

"Move the whole screen up when keyboard opens."

The actual requirement is:

THE FOCUSED INPUT MUST BE VISIBLE.

Example:

If a form has:

Input 1
Input 2
Input 3
Input 4
Input 5

and the user taps Input 5:

The screen should automatically scroll enough so Input 5 is above the keyboard.

If the user then taps Input 2:

The screen should reposition appropriately so Input 2 remains visible.

Do not force the entire page to stay permanently shifted upward.
